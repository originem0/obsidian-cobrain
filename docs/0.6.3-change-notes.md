# 0.6.3 · 跨设备会话合并与文档精简

0.6.2 的会话同步保护不会丢数据，但两种常见情况会生成多余的副本：一台设备上的面板内容已经过期，用户在上面继续编辑；恢复快照比主文件先同步到另一台设备。本版改为按改动合并，只在两边的改动确实冲突时才另存副本。

## 会话同步

- 保存时以本机上次读到的版本为基准，分别比较本机和磁盘上的改动。一边追加了回答、另一边只改了草稿或材料，会自动合并；只有两边各自追加了不同的消息，或写了不同的草稿、改了不同的材料时，才另存为「· 同步副本」。
- 另一台设备已经发出的草稿，不会因为本机还留着旧草稿而复活。
- 发送前、切回窗口或从后台恢复时，面板先接上其它设备的更新，不在旧内容上继续追加。
- 会话文件记录每台设备的写入次数，据此判断一份快照是否已被后来的写入包含，不再按内容猜测。另一台设备改过的草稿，不会再被误判为丢失的写入。
- 恢复快照只由写下它的设备判断：本机的写入没落到主文件时直接补写回原会话；被并发写入覆盖且无法合并时才保留为「· 恢复副本」。另一台设备的快照比主文件先同步到时，不再生成重复副本。与主文件一致的快照保留 14 天后清理。
- 设备标识保存在本机，不随库同步。Obsidian 1.8.7 以前没有设备本地存储，每次启动使用临时标识：合并照常，只是重启后找回中断写入的能力会退化。

## 其它修复

- 面板因其它设备更新而刷新时，只在草稿确实变化时重设输入框，正在输入时光标不再跳到末尾。
- 浏览器验证脚本在运行结束后删除临时浏览器配置，不再在 `.audit/ui/` 下堆积。

## 文档

文档精简为 README、使用手册和当前版本的改动说明。README 负责概览、安装、数据边界与验证，具体用法集中在使用手册，原实践演练的示例并入手册，提示词审查中的人工验收案例移入 README。更早的版本说明以 GitHub Releases 为准；2026 年 6 月的设计与计划快照、0.5.x 演练等过时文档已删除，仍可在 Git 历史中查阅。

## 升级

安装包 `cobrain-0.6.3.zip` 包含 `main.js`、`manifest.json`、`styles.css`，三个文件也单独提供。替换 `.obsidian/plugins/cobrain/` 中的这三个文件，保留 `data.json`、`sessions/` 与 `index/`。桌面重新加载插件，移动端同步后重启 Obsidian。最低 Obsidian 版本仍为 1.7.2，没有新增运行依赖。

0.6.2 留下的恢复快照没有写入次数记录，首次启动时按 0.6.2 的规则处理一次：内容已在主文件中的直接清理，否则保留为「· 恢复副本」。

建议所有设备都升级。升级过渡期里，0.6.3 遇到 0.6.2 写回的会话会按内容合并，不会用自己的旧快照覆盖对方写入的新内容；但仍在运行 0.6.2 的设备会按旧规则处理快照，可能把本版的快照另存为「· 恢复副本」，全部升级后不再出现。
