# Cobrain 使用手册

适用于 0.6.3，更新于 2026-10-27。本版变化见[改动说明](0.6.3-change-notes.md)；安装、数据边界与验证命令见[项目说明](../README.md)。

## 开始讨论

先打开要讨论的 Markdown 文档，再新建会话。顶部材料行会显示文档名，后续问题只围绕明确附加的材料与这段聊天展开；切换编辑器里的文档不会改变已有会话的范围。模型不会在后台替你搜索全库，普通对话也不需要嵌入端点。

给一个具体任务，比泛泛地问更容易得到能用的回答，例如：

```text
解释这篇文章如何区分相关性与因果关系。
先给核心判断，再指出作者用哪项证据支持它。
```

文档每轮读取最新内容，当前编辑器里还没落盘的修改也会读到。没有附加文档时只使用聊天内容。文档很长时，会在文内选择相关小节，并提示本轮用了节选。

## 讨论选文与对照材料

想只讨论一段话，在编辑模式选中文本，运行「讨论选中文本」或用右键菜单。这段原文作为快照保留，源文档之后的修改不会改变它；同篇的全文引用会被移除，需要全文时在材料管理中重新添加。

```text
这里从两个现象共同出现，推到了一个因素导致另一个。
这一步成立需要补哪项证据？
```

想对照几篇文章，点击顶部材料行，再点「添加文档」。在这里也可以移除材料，或选择「改为当前文档」。改变范围总是明确的操作。

## 观点归属

材料里可能有他人的文章、摘录或 AI 生成的内容。材料管理中的归属选择（归属未确认、我的笔记、外部材料、AI 整理）只标注该材料，不修改原文件；没有明确确认时保持「归属未确认」。文档 frontmatter 中的 `author` 和 `source` 也会作为来源说明进入上下文。

你的判断与原作者的论点分别处理。即使标为「我的笔记」，也不代表其中每句话都是你现在认可的立场，对话中的修正和反驳同样重要。追问、沉默或要求改写、整理，都不等于认可副脑的判断。可以明确保留意见：

```text
我理解作者的解释，但还不认可这个因果结论。
请检查它是否排除了共同原因。
```

整理出来的笔记带有 `cobrain_generated: true` 标记，之后作为材料时也不会默认视为你原有的立场。

## 会话与长对话

顶部历史按钮可搜索并继续旧会话，旁边的加号新建会话。历史记录与面板分离，关掉面板不会删除会话；桌面可从更多菜单新开独立面板，手机用同一界面切换。每个会话的完整消息和未发送草稿单独保存，并保留上一份备份。

停止回答或切换会话会保留已经输出的部分。失败或未完成的提问旁边有「继续回答」，不会重复插入原问题。重命名和删除会话都在更多菜单中；删除需要确认，已保存的笔记不会删除。

界面先显示最近的记录，点「显示更早的记录」按页展开，显示范围不影响完整记录的保存和导出。发给模型的内容按估算容量组织，默认输入预算 24000 token，可在高级设置中调整；这是插件的预算，不是对模型实际容量的检测。超出预算时，先把较早的消息整理成连续摘要，再发送近期原文；摘要失败时停止本轮，不会跳过一段旧消息继续回答。摘要不是逐字记忆，需要原话时查看历史或导出完整会话。

## 推敲、概念图与保存

更多菜单中的「推敲观点」检查当前讨论的主张，应注明是谁提出的、指出影响结论的缺口；论证充分时也应说明在哪些条件下成立。「生成概念图」应区分相关性与因果、作者主张与副脑假设，材料不足时可以少画节点。这些都由提示词引导，图的格式和关系仍需审阅，生成不等于验证。

「整理为笔记」提炼判断与未决问题，保存前可以修改标题和正文，也可以附上你的提问。检查是否留下了判断的理由、会改变结论的限制，以及真正未解决的问题。尚未认可副脑的推论时，可以改写成：

```text
原作者认为干预证据可以支持因果判断。
讨论提出共同原因仍需排除，这项解释尚待验证。

> [!question]
> 文章中的干预例子是否排除了共同原因？需要回到实验设计核对。
```

只有确实未解决的问题才写 question callout，未确认存在的笔记目标保留为普通文字。

「导出完整会话」不调用模型，保存全部提问和回答，包括界面还没展开的早期记录，输出到笔记目录下的「会话记录」。它和附上提问的整理笔记是两回事。

## 设置与提示词

打开 Obsidian 设置中的 Cobrain 页面。文本端点用于对话，嵌入端点只在可选资料检索时需要。高级设置包含长对话输入预算、概念图和索引范围。所有分区可同时展开，设置页纵向滚动，窄窗口中的控件会换行。

模型名称可以直接填写；「检测」从端点拉取候选供选择，只是辅助，端点不提供 `/models` 也能使用。嵌入模型在离开输入框时才保存，更换后旧索引会清空，需要在桌面重建；移动端不能更换嵌入模型。API Key 以明文保存在库内插件数据中，同步插件目录时密钥也会同步。

「副脑人设」影响普通对话，「概念图」影响概念和关系的选择，「笔记综述」影响保存前的整理。推敲观点和长对话摘要使用独立策略，修改副脑人设不会同时改变它们。升级时，未改动的旧默认提示词自动更新，自定义内容保留；点某一项的「恢复默认」只重置这一项。

## 需要其它资料时

要讨论一篇已知文档，直接添加即可，不必先建索引。需要从库里找其它资料时，先在高级设置的「索引范围与诊断」中启用可选索引、明确填写允许目录并配置嵌入端点，再在桌面运行「重建允许范围的索引」。允许目录留空表示不索引任何文档，填写 `.` 才表示允许整个库；排除目录和隐藏目录始终优先，已有索引也会按最新的允许范围过滤。

从更多菜单打开「手动查找其它资料」，可以进一步限定本次搜索的目录，或主动选择全部允许索引的范围。结果不会自动交给模型，只有主动选中并添加的才进入会话。桌面负责建立和更新索引，移动端只读同步来的索引；直接讨论文档不需要等待索引。

## 手机与键盘

普通回车换行，点击发送按钮提问；桌面回车发送，Shift+Enter 换行；Ctrl/Cmd+Enter 在移动端的硬件键盘上也能发送。中文输入法确认候选时不会误触发送。底部只保留输入框与发送/停止。

回答期间可以继续起草下一问。完成后不会主动打开键盘，往回阅读时也不会被拉到底部；需要追上最新消息时点「回到最新」。

## 跨设备使用

插件目录中的 `sessions/` 保存完整会话，`data.json` 保存设置及迁移备份，`index/` 保存可选索引。同步这些目录时，会话和密钥也会随同步工具走。

两台设备编辑同一会话时，插件以本机上次读到的版本为基准合并两边的改动：一边追加了回答、另一边只改了草稿或材料，会自动合在一起。只有两边各自追加了不同的消息，或写了不同的草稿、改了不同的材料时，才把本机内容另存为「· 同步副本」，两份都保留。发送前、切回窗口或从后台恢复时，面板会先接上其它设备的更新；打开历史会话列表时会重新读取，能看到其它设备新建的会话。

同步工具有时按「后写覆盖」丢掉某台设备的写入。每台设备都留有自己写入的快照，下次启动时检查：能合并就写回原会话，否则保留为「· 恢复副本」。快照只由写下它的设备判断，另一台设备的快照比主文件先同步到时不会被当成丢失；与主文件一致的快照保留 14 天后清理。Obsidian 1.8.7 以前没有设备本地存储，重启后找回中断写入的能力会退化，合并本身不受影响。

## 升级

从 [GitHub Release](https://github.com/originem0/obsidian-cobrain/releases/latest) 下载安装包，将 `main.js`、`manifest.json`、`styles.css` 替换到 `.obsidian/plugins/cobrain/`，保留 `data.json`、`sessions/` 与 `index/`。桌面重新加载插件，移动端同步后重启 Obsidian。需要 Obsidian 1.7.2 或更高版本，更早的版本会停留在 0.6.1。建议所有设备都升级：仍在运行 0.6.2 的设备会按旧规则处理恢复快照，可能另存出多余的「· 恢复副本」。

0.5.x 的三个草稿会自动迁为独立会话，旧版已经丢弃的原文不能从摘要恢复。以前的配图文件和笔记保留，但不再提供图像生成。

## 能力边界

Cobrain 不会自动联网核验、检查笔记链接目标或在后台搜索全库。材料标注的出处只是来源说明，不代表已访问并核验。长文使用节选时，判断只能覆盖已发送的部分；旧摘要不是逐字引文。

提示词引导模型的行为，不保证事实、归属或 Mermaid 格式正确。需要核对原话时回到文档、历史记录或完整导出。
