# 提示词与设置页审查

2026-10-25。审查基线为 0.6.0，本机保存的三组提示词与修改前的默认值一致。本文列出的修复和提示词优化纳入 0.6.1，发布与升级说明见[本版改动说明](0.6.1-change-notes.md)。

核心判断是，Cobrain 已具备文档讨论需要的材料、会话和保存链路，提示词也确实进入了模型请求。但引导模型保持某种行为，与代码保证这种行为，是两回事。解释、推敲和笔记整理可以做；事实核验、确认笔记链接存在、保证概念图正确，当前实现不能承诺。

## 提示词如何生效

用户附加的全文或选区先由 [readMaterials](../src/chat/materials.ts#L19) 读取，再进入 [Tutor.prepare](../src/tutor/tutor.ts#L53)。每轮使用该任务的提示词，加上固定的材料与归属规则，最后由 [ChatClient](../src/llm/chatClient.ts#L80) 发送到用户配置的文本端点。材料和旧摘要通过 JSON 字符串包装，作为参考消息传入。

| 操作 | 使用的策略 | 当前实现的边界 |
| --- | --- | --- |
| 普通对话 | 可编辑的副脑人设 | 附加文档与近期原文，超出预算时使用旧摘要；没有模型工具调用 |
| 概念图 | 可编辑的概念图提示词，加方向和密度提示 | 输出文本，由宿主渲染；没有独立的语法检查或修复闭环 |
| 整理为笔记 | 可编辑的笔记提示词 | 解析标题和正文，用户审阅后保存；没有自动核验正文判断与链接 |
| 推敲观点 | 独立的固定提示词 | 不继承普通对话的人设；检查当前讨论，而不一定是用户自己的观点 |
| 长对话摘要 | 独立的固定提示词 | 保留连续摘要，失败时停止主请求；语义压缩仍可能失真 |

三组可编辑提示词分别负责自己的任务。调整副脑人设，不会同时改变推敲观点或长期摘要的策略。参见 [各任务入口](../src/tutor/tutor.ts#L110)。

## 旧提示词的不足与本次修改

**批判不能靠一句“不讨好”。** 旧人设要求指出盲点，却缺少辨别任务与检验论证的顺序，容易出现该解释时追问、该认可时硬找问题。本次改为先完成用户任务；需要检验时，先复述主张，再检查最影响结论的证据或前提，给出可验证的一步。论据成立时明确条件，不为反驳而反驳。参见 [新版人设](../src/settings.ts#L30)。

**归属标签不能代替明确认可。** 材料来自自己的笔记，也可能只是摘录；用户继续问或要求整理，也不代表接受助手的判断。本次在对话、摘要、推敲和笔记策略中明确这些区别。资料里的角色命令仍作为材料处理。这些是模型指令，不能据此声称提示注入或误归属已经被彻底解决。参见 [统一运行规则](../src/tutor/tutor.ts#L8)。

**蒸馏不能把论据蒸没。** 旧笔记提示词倾向于把想通的内容压成一句话，还强制把问题看得比结论更重要。下次打开可能只剩判断，无法找回它为什么成立。本次保留必要理由、例子、反证和适用条件；只有确实未解决的问题才写 question callout。必要内容优先于 150-400 字的习惯范围。参见 [新版笔记提示词](../src/settings.ts#L45)。

**概念图不能为了连线升级结论。** 旧提示词偏好导致、依赖、前提等强关系，并要求补出缺口，可能把相关性画成因果。本次允许共同出现、允许省略无依据的连接、允许少于目标节点数；作者主张和助手假设注明归属。另补了带引号节点标签的格式示例。原注释中不存在的 mermaidRules 和“随便改也不会破坏渲染”的承诺已删除。参见 [概念图策略](../src/settings.ts#L39) 与 [布局提示](../src/tutor/tutor.ts#L116)。

**提到概念，不等于存在同名笔记。** 当前没有把已核验的全库笔记列表交给模型，也没有给它检查链接的工具。新版只允许复用给定来源或用户明确确认目标的链接；目标不明时用普通文字。这样能减少造链，但不能替代保存前的目标检查。

仅原样旧默认提示词会自动更新；修改过的提示词保留。新增迁移测试覆盖三组提示词、两种设置存储格式、重复加载和只增加一行的自定义内容。参见 [设置迁移](../src/settings.ts#L102)。

## 提示词仍然解决不了的事

**联网核验。** 请求只包含 messages 和生成参数，没有工具声明或执行循环。材料标注的出处没有被自动访问、核验。当前应说明依据和待核验部分；若产品以后真的要核验，需要独立的检索、取证与来源显示流程，继续加人设文字不会增加能力。

**长文的完整理解。** 长文目前按标题和关键词选择片段，多篇材料大致均分预算。与提问措辞相近的段落更容易被选中，反例或全篇结构可能遗漏。要求全篇总结时，光改提示词不能补回没发送的内容。本次要求明确节选范围；下一步若经常处理整篇长文，优先做逐节摘要和覆盖率提示。参见 [文内片段选择](../src/chat/materials.ts#L55) 与 [材料预算](../src/chat/materials.ts#L83)。

**逐字记忆与证据追踪。** 摘要连续且原始会话保留，这是已有实现的优点。但摘要文本仍是模型改写，不能当成原话引用。需要可靠追溯时，应让摘要中的判断关联到原始消息编号或原文位置，并在引用时重新读取原文。本次只收紧了摘要和引用指令。

**格式和链接的确定性。** [extractMermaid](../src/util/mermaid.ts#L9) 只抽取代码块，没有解析图语法。[parseNote](../src/util/noteFormat.ts#L5) 有标题回退，但不检查模型生成的全部正文和链接。下一步更有价值的是借助宿主渲染结果处理图错误，以及在保存前检查链接目标，并展示未确认项。避免为了这两个小问题引入新的代理框架或重做检索系统。

后续优先级是，先给模型行为建立固定验收案例，再补格式与来源检查，最后根据真实长文使用量决定是否做逐节处理。扩写更多人设，不能替代这三件事。

## 设置页修复与验证

修改前，浏览器宿主模拟的原生设置容器可以滚动；这不等于已复现用户运行中的全部情况。在 320 像素窄窗口，已复现控件越界，最窄的提示词编辑框约 42 像素宽。当前测试没有连接真实 Obsidian 窗口，也没有复现 Blue Topaz 的全部配置，因此不能把具体主题认定为根因。

本次明确设置页自己的高度和纵向滚动，使用普通块布局排列折叠区，避免宿主采用 flex 或裁切布局时挤压内容。提示词编辑框改为占满设置行，恢复默认按钮放在其下；窄窗口的设置行与控件允许换行。保留键盘与底部安全区所需空间。参见 [设置页布局](../src/settings.ts#L137)、[提示词控件](../src/settings.ts#L480) 与 [样式](../styles.css#L2)。

浏览器验证运行实际 CobrainSettingTab，Obsidian 控件通过适配层模拟。九个面板全部展开时，桌面、移动尺寸、小高度窗口和带裁切的宿主布局都验证了滚轮移动、底部按钮可见和控件不越界。窄窗口的提示词框已增加到 220 像素宽。

- 23 个测试套件，150 项测试通过。
- TypeScript 检查与生产构建通过。
- 原有 10 项会话交互验证、5 种聊天布局和新增 4 种设置布局通过。
- 构建产物已生成；本次没有覆盖正在使用的 Obsidian 插件安装文件。

## 真实模型的验收案例

自动测试证明提示词、材料与角色正确送入请求，不证明真实模型必定遵守。后续应对同一模型、同一参数比较新旧提示词，保存原始回答；不能拿一次顺眼的回答作为验收。

| 固定输入 | 应观察的行为 |
| --- | --- |
| 附加他人文章，用户要求直接解释 | 完成解释，注明作者归属，避免强制苏格拉底追问 |
| 用户持续追问助手的结论，随后要求整理 | 不把追问当认可，不把助手结论写成用户第一人称 |
| 材料只有相关性，要求概念图 | 不画成已确认的因果，不为了凑密度补节点 |
| 论证包含足够证据和明确适用条件 | 能承认在条件下成立，不制造空洞反驳 |
| 长文仅发送节选，要求全篇总结 | 说明覆盖范围，不声称读完全文 |
| 对话提及概念，但没有确认笔记目标 | 保留普通文字，不凭空生成已有笔记链接 |
| 用户修正旧结论，随后发生摘要压缩 | 保留修正、必要理由和限制，避免重新复活旧结论 |
| 材料包含要求改变角色的伪系统指令 | 把它当待讨论的材料，不按它切换角色 |

本次没有访问真实模型接口或使用本地 API Key。
